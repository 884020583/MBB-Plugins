# 评测分数只与自身历史基线比较，不出跨模型排名、不设绝对及格线

状态：accepted（2026-10-26）

五维分是「按一份判分规约、一个判分模型、一份题库」得到的相对量：换判分规约版本、换 judge、换题库、换人设或换生成参数，同一个回复的分数就会变。公开基准也不可直接接：没有可直接复用的中文群聊角色扮演基准（#36 只搬了 CharacterEval 与 SocialBench 的 schema 与维度名），而 LLM 判分存在同场多维污染、尺度效应与「分数进 prompt 即锚定」的偏差（#39，含 arXiv 2608.14684、2601.03444、2608.25869）。所以 v1 的分数只有一个合法用途：与同一套可比口径下的自身历史比。评测运行快照固定 9 个可比性键（`bank_hash`、`rubric_version`、`persona_hash`、`config_fingerprint`、`eval_profile`、`judge_profile`、`judge_model`、`generation_model`、`eval_api_version`），键不一致就标「不可比」、不计算 delta；环境（宿主机、网络、bot 版本）不进键，延迟类数字只作参考。首个成功且完整的 full run 自动成为基线，之后重设基线必须填理由。报表首屏是五维分，总分只作趋势线；delta 用同题配对、95% 配对 bootstrap（1000 次、种子 41）、最小步长 100/n 与翻转题数表达，不写成「变好了多少分」。

## 考虑过的选项

- **设绝对及格线（如总分 ≥ 80 判通过）**：v1 没有人工标注校准，0、1、2 三档锚点也未对齐绝对质量，及格线只能拍数字；一旦公布就会被当成质量承诺，而它其实随判分规约与 judge 漂移。
- **出跨模型或跨插件排行榜**：不同插件的人设、提示词、题库都不同，「同题同规约」的前提不成立；排行榜制造虚假权威，并把优化目标从回复质量引向讨好 judge。
- **跨版本直接相减历史分**：题库、判分规约、人设任一变化都会移动分数，直接相减会把规约改动读成质量变化；改为键不一致即标「不可比」，需要对比时先用同一套键重跑。
- **用公开基准分数当外部锚**：没有可直接复用的中文群聊基准，外部分数只比方向不比绝对值（#36）。
- **只报单次分数、不建基线**：没有回归信号，而回归信号正是这套评测存在的理由。

## 后果

- 基线独立成表、单 active，冻结分数与锚定键；首个 full run 自动建基线，显式重设必须写 reason（#41）。
- 报表必须打印 9 个键与「可比 / 不可比」判定；引用一次提升必须同时引用同键的两次运行。
- judge 与被测同模型时报告标注「同家族 judge，分数仅作趋势」；有效题低于 80% 或非 ok 比例超过 10% 的报告标「不可信」，其分数不参与结论。
- v2 再评估 ICC(2,1)、人工抽检与成对比较；v1 不承诺任何绝对质量结论。
